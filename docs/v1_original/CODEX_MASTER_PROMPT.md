# CODEX MASTER PROMPT — MIRROR: LAST EARTH

> **실행 우선 개발 명세서.** 게임 타이틀은 `MIRROR: LAST EARTH — 마지막 지구인`. 우선 `STORY_BIBLE.md`, `BEHAVIOR_MATRIX.csv`, `SCIENCE_AND_ETHICS.md`까지 전체를 읽고 해당 자료를 구현의 단일 진실 공급원(single source of truth)으로 삼는다. 과거 축제 기획은 완전히 폐기한다. 이 파일이 못 다룬 세부 장면은 STORY_BIBLE을 따른다. 질문을 되돌리지 말고 주어진 기본값으로 완성하고, 검증하지 못한 항목은 정직하게 밝힌다.

## 0. 납품 임무 (우선순위)
1. 한국어 2D 픽셀아트 게임: **지구 종말 오프닝에서 첫 네 좌석을 선택하고 → 비행·화성 착륙·기지생존·첫날 규칙까지 8챕터 완주**, 플레이 약 30분.
2. **귀엽고 인상적인 화면**: 기존 판타지 2.5D 도트 게임의 추상적 감성(2등신 캐릭터, 레이어형 맵, 풍부한 소품)만 참고. 기존 게임 IP의 캐릭터/맵/스프라이트/로고/색상 구성/이미지를 복제·트레이싱·추출하는 행위 금지. 오리지널 우주/화성 세계관.
3. 실제로 클릭·이동·작업·퍼즐을 수행하는 게임. 텍스트 3지선다 48개, 일반 설문 웹, 비작동하는 UI, 아름다운 시작화면 뒤 하얀 카드만 반복하는 결과물 금지.
4. 탑승 명단·아이템·자원·대사·미니게임의 분기 일관성 및 복구 가능성.
5. 행동 로그의 기회 단위 정확한 측정/과학적 과장 방지/정직한 결과.
6. 데스크톱/모바일/접근성, 로컬 저장·재시작/브라우저 테스트/빌드 완료.

## 1. 기술 스택과 실행 계약
- Vite + TypeScript(strict) + Phaser 3 (2D 맵/스프라이트/애니메이션) + 독립 DOM/CSS UI(대화창, 승선명단, 슬롯, HUD, 미니게임, 결과 그래프). 경량, 정적 빌드 가능한 구조. 필요할 때만 Phaser 플러그인 사용.
- 외부 유료 API, 로그인, AI 모델, CDN 의존성, 추적 SDK, 백엔드 없이 작동. 패키지는 npm으로 빌드하고 빌드 후 자산은 로컬에서 제공.
- `npm run dev`, `build`, `typecheck`, `test`, `lint`, `test:e2e` 스크립트 제공. Vitest, 가능하면 Playwright E2E. Playwright 환경 설치 불가시 정직하게 기록.
- 게임 state 변경은 중앙 `dispatch()`/reducer를 통한 원자적 트랜잭션. 캐릭터 렌더 상태·스토리 상태·점수 이벤트를 직접 분리해 UI 이중 클릭으로 서로 어긋나지 않도록 한다.
- 게임 스토리 JSON/TS 데이터와 기능 코드를 분리. 대사/선발 NPC/기술 대체 루트를 미리 정의해, **15가지 C1 승선 명단 조합 전부** 같은 장면 수로 진행되도록.
- 프로젝트 내 `README.md`, `MEASUREMENT_LIMITATIONS.md`, `TEST_REPORT.md`를 생성하라.

## 2. 아트 디렉션 (가장 중요한 UX 품질 게이트)
**아트 철학:** '바깥 세계는 거대하고 무섭지만, 그 안의 사람들은 손바닥만큼 귀엽다.' 지구는 차가운 남색/재색/경보 코랄, 우주선은 크림+네이비+청록 조명, 화성은 살구/테라코타/자줏빛 그림자, 제로돔 내부는 크림/옅은 민트/따뜻한 노랑. 비극을 조롱하지 말고 캐릭터의 귀여움으로 온기를 만든다.
- 탑다운~3/4 시점의 수작업 도트 스타일. 16/24/32px 타일. 2~2.5등신의 둥근 캐릭터, 큰 머리·명확한 눈·볼·헬멧·모자 실루엣. 원본 스프라이트 24×32 또는 32×40, 화면 배율 2~4배(정수 배율), pixelated/nearest-neighbor.
- 최소 인물/로봇: 플레이어 1, 조종사 담 1, 후보 6, 안내 드론 콩별 1 = **사람 8명+로봇 1**. NPC 각각 고유 헤어/복장/도구/표정. 정지/걷기 4방향 2~4프레임, 3개 표정(걱정, 안도, 기쁨 등). 선택 여부가 시각적으로 반영.
- 맵 4개 핵심 배경(지구 지하발사장, 아크-06 내부, 화성 표면, 제로돔 내부), 챕터 변형 레이어 포함하여 화면별 확실한 차이. 복도·사물함·로켓창·기계실·농장실·로버·얼음층·작은 화분·지구 사진 같은 소품 실체화.
- 캔버스의 임시 사각형만으로 사람/배경 구현 금지. 이미지 생성 없이도 재현 가능한 **독창적 픽셀매트릭스/프로시저럴 스프라이트**나 직접 제작한 오리지널 PNG/SVG를 사용. UI 텍스트를 Canvas에 1px 폰트로 그려 가독성을 해치지 말고 DOM에 렌더.

## 3. 장면과 인터랙션 계약
- 모든 챕터의 목표, 장면·원인·대사·분기·결말은 `STORY_BIBLE.md`의 C1~C8을 구현한다. 8개 챕터가 온전히 이어지고, 시작/끝/재개/스킵 안내가 동작.
- 맵에서 WASD/방향키 또는 클릭 목적지 이동, 모바일 터치 상호작용 또는 탭 목적지 이동. 모든 목적지까지 실제 접근 가능, NPC 접근 시 초상/대화/행동 메뉴. 단순한 맵 일러스트 위 버튼 나열에 그치지 않는다.
- C1: **6명 후보의 개별 NPC 카드**와 4석의 드래그/탭 배정. 배정·취소·교체·비교·최종확정. `selectedIds.length === 4` 전에는 확정 버튼 비활성. 보드에 선택 4/남은 2 실시간 표시. 선발되지 않은 사람은 이후 장면에 출현하지 않음.
- C2: 수하물 12kg 제한 배치 미니게임, 재조정 가능. 선택한 보조 도구에 의해 관련 챕터 추가 선택지 달라짐, 필수 생존 장비는 기본 지급.
- C3: 기밀 센서/밸브 선연결 + 점검, 안전 조건을 충족해야 하지만 좌석 선택과 무관하게 항상 해결 가능.
- C4: 선내 물 재활용 시스템의 관로/우선순위 퍼즐 + 선택적 인물 대화/지구 과거영상. 자원 회복/지원 대체.
- C5: 3개 지점의 정보 비교 + 착륙 보조 패널 조작 + 화성 착륙/로버 이동. 화성 외부 인물은 우주복 의무.
- C6: 전력/산소 보충/CO2 제거/기압 관리 계통의 진단 및 안전한 전력 배분. 과장된 현실 의학 수치 아님.
- C7: 탐사 지점 정보 레이어/로버 탐사/시추/수질 처리. 채굴 대상은 수빙; 지표에 흐르는 물 표현 금지.
- C8: 정착지 운영 초안/부담 조정/투표 또는 합의/첫 규칙 완성, 4종 서사 엔딩.
- 각 장은 **적어도 4개의 실제 상호작용 단계 + 서로 다른 자발적 경로 최소 2개 + 실질적 시각 변화**가 있어야 하며 텍스트 선택지만으로 장 전체를 대체하지 않는다.
- 뚜렷한 캐릭터 특성 살리기. 상황 설명은 짧은 대화 1~3문장씩, 어려운 공학용어는 콩별의 친절한 한 문장 설명. 챕터마다 한 번은 조용한 인간적 장면(따뜻한 말/화분/기억/장난)을 넣어 재난만 반복되지 않게.
- 스토리 자원(기본값, **게임 내 추상 단위**) 예시: `power=65`, `oxygenReserve=70`, `water=60`, `food=60`, `trust=50`, `archive=20`, `habitatIntegrity=70`. 각 0..100 클램프, critical 상황이면 복구·비상설비로 다시 진행. 플레이어의 작은 실수로 즉시 영구 게임오버·동료 사망 처리하지 않는다. 초기에 보여주는 카운트다운은 픽션이며 브라우저에서 초 단위로 실제 삶/죽음 판정 금지.
- 실물 우주선 규격/질량/단위/안전 프로토콜을 진짜 NASA 절차처럼 묘사하지 말 것. 실제 조건은 SCIENCE_AND_ETHICS 참조.

## 4. 스토리·상태 불변식
```ts
type CandidateId = 'harin'|'taeo'|'seojin'|'morae'|'dodam'|'jio';
type ChapterId = 'C1'|'C2'|'C3'|'C4'|'C5'|'C6'|'C7'|'C8';
type OpportunityStatus = 'unavailable'|'eligible'|'observed'|'skipped';
interface MissionState {
 schemaVersion: 2;
 runId: string;
 chapter: ChapterId;
 sceneId: string;
 crewIds: CandidateId[]; // C1 미확정은 0..4, 확정 후 정확히 4, 중복 불가
 crewLocked: boolean;
 inventoryIds: string[];
 resources: {power:number;oxygenReserve:number;water:number;food:number;trust:number;archive:number;habitatIntegrity:number};
 narrativeFlags: Record<string, string|number|boolean>;
 opportunities: Record<string, OpportunityRecord>;
 events: ObservationEvent[];
 analysisOptIn: boolean;
 endingId?: 'dawn'|'memory'|'together'|'rebuild';
 completed: boolean;
}
interface OpportunityRecord { id:string; status:OpportunityStatus; evidenceEventIds:string[]; finalAction?:string; }
interface ObservationEvent { id:string; chapter:ChapterId; opportunityId:string; actionType:string; actionId:string; context:Record<string,string|number|boolean>; timestamp:number; }
```
- C1 확정은 `crewIds` 정확히 4, 모두 6개 후보 ID에 속하며 중복 불가. 출발 후 변경 금지. 맵의 NPC 스폰, 대사, 화상 통화, 물품, 엔딩 모두 crewIds에서 파생.
- 결여된 특정 전문인 때문에 퀘스트 막힘 금지; 무인 로봇/담/콩별/예비 장비가 같은 목표에 달하는 더 긴 보조 경로 제공(전문가 존재 시 1단계 단축이나 개별 대사만).
- `MissionState`는 schemaVersion=2 네임스페이스 `mirror:last-earth:save:v2`. 오래된 모아마을 세이브와 절대로 혼용하지 않음. 저장 값 JSON 검증 + 실패시 복구/새시작 안내. 자동저장 후 재시작해도 추가 로그 중복 생성 금지.
- chapter progression은 명시적 FSM: `intro -> C1_setup -> C1_roster -> C1_locked -> C2... -> C8_ending -> results`; scene을 벗어나는 퀘스트 필요조건 검사. 막힌 상태에서는 힌트 및 안전한 재시도 제공.
- 모든 보조 NPC가 없는 루트를 고려한 fallback dialogue. 예: `getRepairDialogue(crewIds)`는 태오→지오→담 우선. 참고 대사가 기술 능력을 과도하게 왜곡하지 않게.
- `crewIds`와 `inventoryIds`·자원 감소 등에 RNG 사용할 때 run seed 저장. 같은 상태 복구 후 미래 결과가 달라지지 않게 PRNG 상태 저장 또는 모든 선택결과 순수 결정 함수 사용.

## 5. 성격 관찰: 측정 알고리즘 고정
`BEHAVIOR_MATRIX.csv`에 있는 정확한 **C1-O01..C8-O06 총 48개 기회**를 `src/analytics/opportunities.ts`로 가져와 정의. 8개 `STORY` 기회는 점수에 반영하지 않으며 나머지 40개는 모두 실질 UI 액션/조건과 연결한다.

### 계측의 의미
- **기회(opportunity)**는 버튼 한 번이 아니라 동일 맥락에서 의미 있는 자발적 행동을 할 기회를 뜻함. `eligible`이 선행되어야 관찰/건너뜀 기록 가능. 없던 NPC·도구 때문에 기회가 없다면 `unavailable`로 기록하고 점수에 0을 더하지 않는다.
- 이벤트는 실제 커밋된 상태 변경에만 추가한다. 한 기회 최종 지표값은 1회 확정; 같은 화면 새로고침/중복 클릭/뒤로가기/탭 전환으로 중복 점수 금지.
- 자발적 정보 확인, 계획을 세운 다음 수정하는 빈도, 다양한 해결안 비교, **필수 목적에 종속되지 않은** 다른 이와의 사회적 접근, 타인의 관점을 추가 확인한 행동 등만 가설적 지표로 사용. 원시 반응 속도, 포기한 생존자 정체, 희생, 선발자 직업, 개인적인 유품, 위험감수, 실수, 생사결정, 감정반응을 측정 지표로 사용 금지.
- 다중 지표를 출발점부터 숨김 계산하는 척하지 말고 규칙표와 한계를 README/MEASUREMENT_LIMITATIONS에 공개. 게임 안에서는 세부 채점표만 숨기되, 행동 분석 및 저장에 관한 고지는 반드시 플레이 전에.

### 결과 산출
- Big Five `O / C / E / A / N`: O 새로운 해결안 탐색; C 자발적 점검·계획 유지; E 자발적 사회적 접근; A 타인 관점 확인·협력 조정. **N은 짧은 게임과 위기 상황만으로 추론하지 않으며 v1 결과에 항상 '판단 자료 부족'**. 용어 '외향성'과 '신경성'을 혼동하지 않도록.
- MBTI 유사 지표 `EI / SN / TF / JP`는 정식 MBTI와 별개이며, **감정 vs 논리의 도덕적 우열로 오해되는 매핑 금지**. T/F축은 실제 이 게임에서 충분히 분리측정하기 어려우므로 탐색적 의사결정 정보 선호 지표에 불과함을 설명. 행동사례 없으면 타입 대신 `?`, 근소한 점수면 `X`.
- `extractFeature(opportunity, events)`는 [-1,1] 또는 null을 반환, 각 기회는 고정 상한을 갖고 **하나의 챕터에서 한 특성/축을 과대 반영하지 않도록 챕터별 평균→챕터 간 평균**. 각 trait/axis는 최소 3개 독립 챕터 + 4개 유효 기회에서만 수치 표시. 결측은 평균에서 제외. `unavailable`은 미선발 NPC/옵션 비활성으로 생기는 구조적 결측으로 표시.
- `feature`의 방향은 `scoringRules.ts`에 명시. **선택지 2개 중 한쪽이 성격의 반대라는 가정을 하지 않음**. 예를 들어 말 걸기 행동을 선택하지 않았다는 사실만으로 I 쪽 점수를 강제하지 않는다. 성향의 다른 극을 해석하려면 동등하게 관찰 가능한 행동 맥락이 있어야 함. 이 때문에 구분이 어려울 경우 `X`/`?` 허용.
- 검증 전 점수 0~100은 `게임 속 행동 지수`이며 의학적/심리학적 정확도·백분위·확률 아님. 유효 지표별 `-1..1`을 챕터 균등 가중 평균하고 `round(50 + 50 * average)`로 표시 가능. 학문적으로 검증되지 않은 임시 가중치라고 표기, 추후 교정 가능. 개인정보·집단 평균 데이터 없는 상태에서 사용자끼리 순위를 말하지 말 것.
- 결과 카드의 사례 문구는 **실제로 저장된 기회/이벤트만** 사용하고 해당 챕터에 돌아가지는 않더라도 '그때 무슨 일이 있었나' 상세 보기를 제공. 체력/결정의 희생/탑승 제외 결과를 성격 진단의 근거로 내놓지 말 것.
- 선택된 캐릭터에 따라 탐색 난이도가 달라질 수 있기에, 캐릭터 보너스로 자동으로 성공하는 사건을 마치 자발적인 사용자 행동인 것처럼 가산 금지.

## 6. 인터페이스 상세
- **타이틀:** 푸른 지구가 재로 덮인 듯한 궤도 배경과 선명한 작은 붉은 화성. 귀여운 안내 드론 콩별이 떠다닌다. 버튼 [마지막 배에 타기], [이어하기], [게임 소개], [설정]. 시작 전 재난·이별 소재 포함 안내와 행동 분석 동의/미동의 선택(미동의여도 게임 가능, 결과 분석 없음).
- **메인 HUD:** 게임 화면을 70% 이상 차지하는 귀여운 플레이어와 맵, 상단 현재 상황/진행, 단순 자원바, 오른쪽 퀘스트 카드 (모바일 하단 접이식), 좌측/중앙 캐릭터 대화, 지도 퀘스트 표시. 행동 성격 점수는 HUD에서 공개하지 않음.
- **승선 선발:** 가운데 NPC 초상 6장, 오른쪽 4슬롯(모바일 순차), 각 카드 클릭 시 짧은 소개+필요할 때 상세기록, 좌석 배정 후 시각적 빈 슬롯 갱신, [확정 전 다시보기]. 한 사람을 선택/제외하는 색상은 도덕적 선악 색 구분 금지.
- **게임형 미니게임:** 무게 슬롯, 와이어 연결, 관로 연결, 전력 우선순위, 위치 지도, 로버 경로/시추, 운영 보드. 모두 키보드/탭 대체 조작 제공. 기본 브라우저 input/checkbox 배열만으로 처리하지 말고 시각적 시스템 조작을 구성.
- **대화창:** 2등신 스프라이트 + 표정 변화, 고해상도 한글 본문, 한 번에 1~3문장, 캐릭터별 뉘앙스. 발사장 NPC를 기지에 잘못 출현시키지 않는지 렌더 단위 테스트.
- **엔딩:** 생존 규칙 3문장 + 실사용 선택으로 변형되는 화성 돔 미장센 + 4엔딩 중 하나 + 관찰 근거 기반 빅파이브 5장/MBTI 유사 4축/상황별 행동 차이 + [이미지 저장] [다시하기] [기록 삭제]. 과학적 검사/확정적 '진짜 성격' 언급 금지.
- **접근성:** `prefers-reduced-motion` 준수, SFX 기본 OFF, 자막 대체, 텍스트 크기 조절, 44px 모바일 터치 영역, Tab/Enter/Escape, draggable 요소의 탭 대체 조작. 유저의 성격 점수에 접근성 입력 방식을 반영하지 않는다.

## 8. 개발 단계 (순서 고정, 전 과정 실제로 수행)
1. **Phase A:** 저장소 조사/프로젝트 구성/기본 빌드. 수직 슬라이스: 시작 → 지하발사장 이동 → 콩별 대화 → 6명 카드/4명 확정 → 저장 → 다음 챕터 진입. **여기서 UI 퀄리티와 결정을 먼저 검토.**
2. **Phase B:** 오리지널 아트 제작 (캐릭터 8인+콩별, 발사장/선내/화성/제로돔 4구역), 귀여운 애니메이션, 휴대폰 조작. 적어도 C1과 C6의 동등한 그래픽 수준 목표.
3. **Phase C:** C2~C8의 진짜 미니게임, 서사 분기, 자원/대사, 15개 승선조합 fallback, 4엔딩. 더미 버튼/데모 로그 금지.
4. **Phase D:** `BEHAVIOR_MATRIX.csv` 48개 기회→실제 UI, 센서 로깅, Big Five/유사 MBTI(한계 표시), 결과 증거 카드, 로컬 저장/삭제, 접근성.
5. **Phase E:** typecheck, lint, build, Vitest, Playwright E2E, 실제 브라우저에서 1366×768 및 390×844 확인. 오류 수정 후 재실행. 못 한 검증은 테스트 리포트에 구분해서 기록.

## 9. 테스트 및 수용 조건 (중요)
### 게임
- [ ] 시작 → C1 → C8 → 엔딩 → 성격 리포트까지 사용자 조작으로 완주.
- [ ] C1 6명 중 정확히 4명 선발; 선택 전 0~3명일 때 잠금 금지; 취소·재배정 정상.
- [ ] 6C4=15가지 승선 조합에 대해 `crewLocked` 후 4명이 고정되며 이후 선내·기지 캐릭터가 정확히 일치. 선발되지 않은 사람은 실물 NPC로 재등장 금지.
- [ ] 하린 탑승 / 미탑승 조건에서 각각 독립 대사·회상. 게임 막힘 없음.
- [ ] 태오/서진/모래/도담/지오 각각 미탑승 때 대응 대체 루트 존재. 반드시 6명 모두의 부재 분기를 검증.
- [ ] 8개 미니게임 중 각 한 개 이상 실제 작동. 맵·대화·이동·자원·퍼즐이 장식이 아님.
- [ ] C2 짐 합계 <=12kg; C3 안전 완료 전 발사 성공 처리 안 함; C5 외부 우주복 고정; C6 전력·산소 자원 0..100; C7 수빙 처리 단계.
- [ ] 4가지 엔딩 모두 상태에 맞춰 도달 가능. 어떤 엔딩도 소프트락/갑작스런 사망으로 종료되지 않음.
- [ ] 플레이 약 30분 목표(별도 다수 사용자 플레이테스트 전 정확히 30분 보장 불가).
### 측정
- [ ] 48개(챕터당 6) 관찰 기회 ID 모두 정의되고 모두 실제 장면과 연결. 측정 대상 40개·스토리 전용 8개.
- [ ] 중복 클릭/중복 저장/화면 재진입 시 한 번만 확정; 새로고침 후 점수 결정성 유지.
- [ ] **탑승 선발자의 이름을 바꾸고 행동 과정을 같게 하면 성격 점수가 같음**; 동생 하린 탑승 여부만 달라진 것도 성격 점수에 영향 없음.
- [ ] 서사적 결단/부상·죽음 위험/어떤 생존자 남겼는지/정치 규칙 선택 결과를 점수로 변환하지 않음.
- [ ] N은 판단 자료 부족 고정. Big Five 다른 4영역과 4축에 관찰 부족/중간이면 숫자 또는 4글자 타입 강제 생성 금지.
- [ ] 자료 없으면 `null`/`?`/`X` 처리. 게임 내 대사 중 실제 하지 않은 행동을 결과 증거로 날조하지 않음.
### 기술·UI
- [ ] 로컬 브라우저 저장·이어하기·초기화·동의 해제 동작, 구버전 세이브 거부/안내.
- [ ] 모든 클릭 타깃 모바일 390px 화면에서 조작 가능; 전체 화면에서 중요한 클릭이 오버레이 때문에 가려지지 않음.
- [ ] 키보드 조작/모션 감소/효과음 OFF 기본/텍스트 가독성 충족.
- [ ] 원본 그래픽, 8명 캐릭터 + 1로봇, 주요 맵 4개, 스토리 전반 통일된 디자인.
- [ ] 빌드/테스트/린트의 실제 수행 기록; 실패 시 조치와 미실행 이유 리포트.
